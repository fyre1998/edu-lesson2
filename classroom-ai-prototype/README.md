# 知伴课堂 · 生长素探究

访问 `/classroom/`，无需前端构建。原个人工作台 `/`、账号、资料和对话保留。新课次采用四环节、八组，教师手动推进；原有五环节六组课次按原定义打开。

## 课堂操作

1. 教师用原姓名、课堂邀请码和教师密码登录，创建课次。每次只有一个进行中的课次，归档后可新建。
2. 第 1 至第 8 组各用一台电脑，选择小组、填写邀请码即可进入，不登记学生姓名。页面顶部“查阅本课资料”默认收起，可随时展开；各环节不再显示“概念解释／思考提示”模块。对话与成果区分别滚动。
3. 第一环节填写“感光部位是”“弯曲部位是”，提交“验证菜豆受蓝光刺激部位的实验设计”。教师点击“分发预期结果”后，八组各收到三张教师原图中的一张，按3／3／2随机均衡分配，刷新或重复点击不会重新抽取。未提交的小组也能收到图片并继续完成设计；已提交的小组可以根据评分反馈修改并再次提交，分发时的原始版本及历次修改仍保留。教师可查看各组图片、分发数量并调整图片，但不能将全部小组设为同一结果。
4. 第二环节的“本环节引导”按顺序展示：这种影响的本质是什么；这种影响是抑制还是促进生长；这种影响是光诱导后才产生的吗；这种影响如何使幼苗弯曲。根据已有资料和证据设计实验，解决问题，只提交一份实验设计。波森·詹森与拜尔的资料仅提供初始方法，直接访问未开放资料仍受服务端限制。
5. 第三环节回答“温特的实验相比于此前的实验，该实验解决了什么问题？”。原对话引导保留，成果区只设一个回答框。
6. 第四环节先上传并提交模型图，再将科学家姓名拖动或点击放置到原图上，最后上传未达预期结果后的讨论答案，也可填写文字。模型图和答案图各最多4张；模型提交单独保存版本，完整成果提交时才评分。姓名位置随草稿和版本保存，教师查看和投屏可见。无需转录或额外填写模型空白。全部项目均可跳过；未提供模型图时不能在空图上放置姓名。
7. 所有学生项目均选填，空白或部分作答均可提交。未填写／未上传的对应项目固定记0分，不以聊天代替未交成果；全空提交直接记0分，无需调用AI。已作答内容异步评分，总分100，四环节权重20／30／20／30。评分失败仍显示待重试。教师可查证据、修分及历史量规；新版本替换本环节分数。
8. 教师八组概览约每 5 秒刷新，展示进度、四环节分数、总分和排名。点击小组看原文及版本，支持教师修分和双组投屏。教学提示词与评分量规仅教师可查看。
9. 学生评分在独立的常驻气泡窗显示。有新评分自动展开，可收起或移到左侧，与成果区对照查看。评价分为“做得好的地方”和“这次先改1–2点”：保留有依据的优点，每次只选最多两条修改建议，满分不强行提出不足。点击“修改本组成果”可定位相关输入框，修改后再次提交获得新评价。草稿修改时仍标明评价属于上次提交，新提交待评分时不会冒用旧评价。教师复核后以复核得分为准。
10. 拍照弹窗使用约96%的屏幕宽度和94%的屏幕高度，实时画面与照片预览保持完整比例；拍摄、重拍、确认上传按钮保持可见。摄像头权限与原有文件上传方式不变。

历史评分没有详细AI反馈时，气泡窗会明确显示按得分整理的简短提示；下一次提交后生成具体评价。新增评价保存在已有评分记录中，不更改原始分数或补写历史AI评语。

## 对话、识图与评分模型

主模型通过服务端 `.env` 中的 `AI_MODEL` 配置，当前示例为 OpenRouter 的 `~deepseek/deepseek-flash-latest`。课堂引导、图片分析和成果评分共用这一模型；普通个人工作台文字对话也沿用此配置。`Latest` 会自动指向 Flash 家族的新版本，上课前可用固定样例复核表现。

四环节引导、模型转录和评分请求使用明确的 JSON Schema 约束字段与类型；OpenRouter 只选择支持所需参数的服务端点，返回数据仍由服务器校验。语音转文字由独立的 `STT_MODEL` 负责，切换主模型不需要改变语音配置。修改 `.env` 后需重启本地服务；Docker 部署需重新创建应用容器才能加载新值。

`AI_MAX_TOKENS=8192` 为推理与最终回复预留额度，避免旧的 2000 token 上限在评分前耗尽；达到上限的回复不会保存成完整答案。当前 OpenRouter 配置使用 `AI_REASONING_EFFORT=low`，留空时使用服务商默认推理强度。

## 语音输入

聊天点击“开始说话”，说完点“停止并发送”。转写为文字后与已有草稿合并并自动发送，AI 以文字回复。成果文本框点“语音填写”，停止后只填入对应草稿，仍需学生提交成果。

录音最长 90 秒，单份最多 10 MB；可随时取消。退出、切换课次／环节、页面进入后台会停止录音并丢弃迟到转写。权限拒绝、无设备、静音、格式不兼容和接口失败均有提示。发送失败保留识别文字和重试入口。音频只临时传给转写服务，不作为课堂附件或写入长期存储；文字进入正常课堂记录。

服务端配置（`.env`，不能放在网页源码）：

```dotenv
STT_BASE_URL=
STT_API_KEY=
STT_MODEL=openai/gpt-4o-mini-transcribe
```

空地址和密钥复用 `AI_BASE_URL`、`AI_API_KEY`，请求采用 OpenRouter `/audio/transcriptions` JSON 格式。`STT_BASE_URL` 应填到 `/api/v1`，不是完整接口路径。语音模型与对话／视觉模型分别配置，按服务商用量收费。

2026-09-16 本地实测原定模型被服务商返回 403。本机 `.env` 因此设为 `STT_MODEL=qwen/qwen3-asr-flash-2026-02-10`，同一 OpenRouter 入口下八组并发测试成功。示例文件仍保留计划中的默认值，部署前应检查所选模型可用性。[OpenRouter STT 文档](https://openrouter.ai/docs/guides/overview/multimodal/stt)、[Qwen 模型说明](https://openrouter.ai/qwen/qwen3-asr-flash-2026-02-10)。

本机可用 `localhost`／`127.0.0.1`。其他电脑访问需受信任的 HTTPS；普通局域网 HTTP 地址通常不能申请麦克风。摄像头同样需要安全上下文。[浏览器麦克风要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。生产部署沿用项目根目录 README 中的 GitHub → VPS 流程；公网 HTTPS 可供教室设备使用。

## 保存、权限与兼容

草稿停止输入约 0.9 秒后保存。修订号防止过期草稿覆盖；浏览器会话缓存未同步文字。提交与聊天请求带去重编号。模型转录完成时复核草稿修订号，旧识别不能覆盖新草稿；当前积分只读取最新提交版本。

图片和原有文档上传继续保留单份20 MB限制、每组100份配额和单次成果12份关联上限。第四环节分别读取模型图和讨论答案图，合计最多8张、总计20 MB；其余上传文档不自动解析。语音路由单独设11 MB请求体上限（含multipart开销），仍执行10 MB音频校验。

新增 `lesson_definitions` 保存教学版本和组数；无版本记录的课次按旧版五环节六组读取，不重编号、不修改原作者。新增模型转录、评分、对话进度、聊天去重和转写去重表，不删改原表。教师身份规则、组间隔离、归档只读和旧课记录延续。

四环节预期结果单独保存于 `lesson_expected_results`，不再依赖旧版“处理类型”字段或提前提交。服务启动时为已经开放结果但缺少新图分配的进行中课次自动补发；归档课次原结果图仍可查看。三张图片保持教师原图与“假设性预期结果 · 非实测数据”标记，学生只能读取本组分配的图片。

保持现有单 worker 部署；八组语音可同时转写，每组仅一次在途请求，转写 80 次／组／小时。AI 对话每组滚动一小时最多 120 次请求，服务端每组仅处理一条在途提问，八组之间可并行；前端从保存草稿开始锁定发送，防止连续点击。已完成消息使用同一请求编号重试时直接返回缓存，不重复调用 AI，也不重复计数。模型识别每组一次在途请求；评分任务最多四个同时运行。重启中断的评分可由教师在三分钟后重试。扩展多 worker 前应将进程内限流、锁和任务队列改成共享实现。
