## 访问

测试地址：https://212-50-233-200.sslip.io

点击“创建账号”注册自己的账号。笔记、文件、AI 对话按账号隔离。当前开放注册，AI 尚未配置；其他功能可以正常测试。

临时域名使用 sslip.io 公共解析服务，指向这台 VPS；HTTPS 证书由 Caddy 自动申请和续期。域名解析依赖第三方服务，正式使用时可以换成自己的域名。

## 本次上线完成的步骤

1. 连接 AlmaLinux 9.7 服务器并检查已有服务。
2. 安装 Docker Engine、Compose，设置 Docker 开机启动。
3. 将本地项目源码打包上传到 `/opt/edu`。GitHub 私有仓库保留源码，本次没有在服务器保存 GitHub 凭据。
4. 在服务器生成独立随机数据库密码并保存在权限为 600 的 `/opt/edu/.env`。
5. 构建应用镜像，启动 PostgreSQL、FastAPI 和 Caddy。
6. 申请 HTTPS 证书，从公网验证应用接口。

服务目录：`/opt/edu`。只对公网发布网站的 80 / 443 端口；数据库与后端端口未发布。SSH 仍使用原有配置。

数据库和上传文件使用 Docker 持久化卷；服务配置了自动重启。没有导入本地测试数据库。

## 后续维护

SSH 登录后：

```bash
cd /opt/edu
docker compose ps
docker compose logs --tail=100 app
```

修改配置后重新创建服务：

```bash
docker compose up -d
```

修改源码后重新构建：

```bash
docker compose up -d --build
```

当前部署目录没有 Git 仓库。后续可配置服务器只读部署密钥，再建立 Git 拉取流程；目前可继续用源码包更新。

若只供少数人测试，可以先注册所需账号，再把 `/opt/edu/.env` 中的 `ALLOW_REGISTRATION` 改为 `false` 并执行 `docker compose up -d`。

接入 AI：在服务器 `.env` 设置 `AI_BASE_URL`、`AI_API_KEY` 和 `AI_MODEL`，然后执行 `docker compose up -d`。密钥不写入 GitHub。

换域名：先把新域名解析到 VPS，再修改 `.env` 中的 `DOMAIN` 并执行 `docker compose up -d`。Caddy 会为新域名申请证书。

备份流程见项目 README。不要执行 `docker compose down -v`，该命令会删除数据卷。
